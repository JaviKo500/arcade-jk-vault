This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## Project

Arcade Vault — a platform for playing games online and competing for the highest score. UI copy is in Spanish (retro/neon arcade aesthetic); specs and skills are written in Spanish too.

Development follows Spec Driven Design via the `/spec` and `/spec-impl` commands, based on practices from <https://github.com/Klerith/fernando-skills>. The skill set is installed with:

```bash
npx skills@latest add Klerith/fernando-skills
```

Specs live in `specs/NN-<slug>.md` (numbered, with a `Estado: Draft | Approved | Implemented` header and `Depende de:` links to earlier specs). Read the specs a feature depends on before touching it; when implementing one, mark it `Implemented` at the end.

## Commands

```bash
npm run dev           # dev server (also regenerates AGENTS.md — see below)
npm run build         # production build
npm run start         # run production build
npm run lint          # eslint (flat config, eslint.config.mjs)
npm run format        # prettier --write .
npm run format:check  # prettier --check .
npm run db:push       # supabase db push (applies supabase/migrations to the remote project)
npm run db:types      # regenerate lib/supabase/database.types.ts from the remote schema
```

There is no test script configured yet.

## Skills & tooling

- Use always `/frontend-design` for designing user views.
- `/spec` and `/spec-impl` (fernando-skills): write and implement specs.
- `/add-game` (project skill, `.claude/skills/add-game/`): generates a `specs/NN-<id>-game.md` spec (Draft) to port a game from `references/started-games/` or design one from scratch, then implement it with `/spec-impl`. Its `platform-contract.md` documents the real integration points (engine contract, registry, catalog, scores) — keep it in sync when that contract changes.
- `/msg-commit`: conventional commit message in English from staged changes. Commits follow `type(scope): message` (e.g. `feat(serpentina): ...`, `docs(spec): ...`).
- **PostToolUse hook** (`.claude/settings.json` → `.claude/hooks/format-and-lint.mjs`): every Write/Edit runs Prettier and `eslint --fix` on the file; it exits 2 with the errors if lint errors remain, so fix them rather than ignoring the hook output.
- **Supabase MCP** (`.mcp.json`) is connected to project `fvbuzwmfygecfketwpsr` — use it to inspect tables, run SQL, check advisors and logs.
- Playwright MCP is available for visual checks; screenshots go in `.playwright-screenshots/`.

## Critical: read the docs before writing code

This repo pins `next@16.3.0`, a version newer than most training data and with breaking API/convention changes. **Before writing any Next.js code, read the relevant guide under `node_modules/next/dist/docs/`** (sections: `01-app`, `02-pages`, `03-architecture`, `04-community`). Do not assume App Router APIs work the way they did in older Next.js versions you may recall — verify against these docs first, and heed any deprecation notices found there.

The `AGENTS.md` file (imported above) is regenerated by `next dev` itself (see `node_modules/next/dist/server/lib/generate-agent-files.js`). If it shows as a diff, that's expected — commit it along with your work rather than reverting it, since removing it just causes `next dev` to recreate the uncommitted change.

## Architecture

Stack: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, Supabase (`@supabase/ssr`), Resend (contact email).

### Routes (`app/`)

- `/` home landing, `/about` (with contact form), `/auth` (sign in/up, local session only), `/games` (catalog with search + category filters), `/games/[id]` (detail + top scores), `/games/[id]/play` (player), `/leaderboard?game=<id>` (rankings per game tab).
- `app/api/contact/route.ts` — POST that sends the contact email via Resend; validates fields, has a honeypot (`company`) and an in-memory IP rate limit (`lib/contact-rate-limit.ts`).
- `app/api/health/route.ts` — Supabase health check.
- Root layout's props are typed with the generated `LayoutProps<"/">` helper (from `.next/types`) rather than a hand-written props interface — this is a Next.js 16 typed-routes convention, not a mistake to "fix" if it looks unfamiliar. Layout wraps everything in `SessionProvider`, `Nav` and `Footer`, and loads the fonts (Press Start 2P, JetBrains Mono, Courier Prime) via `next/font`.

### Data (Supabase)

- Clients: `lib/supabase/server.ts` (Server Components / routes) and `lib/supabase/client.ts` (browser). Generated types in `lib/supabase/database.types.ts` — regenerate with `npm run db:types` after any migration.
- Schema in `supabase/migrations/`: tables `games` (catalog, seeded) and `scores`; views `game_stats` (best score + play count) and `leaderboard` (each player's best per game, ranked). RLS: everyone can read; anon can only `insert` into `scores` (`player_name` must match `^[A-Z0-9_]{1,12}$`). New schema changes always go through a new migration file.
- Data access layer in `lib/data/`: server reads `getGames`/`getGame` (`games.ts`) and `getLeaderboard` (`leaderboard.ts`); client-side `insertScore`/`getPlayerBest` (`scores-client.ts`). They return `DataResult<T>` (`{ ok: true, data } | { ok: false }`) instead of throwing; pages render the "SEÑAL PERDIDA" (`components/signal-lost.tsx`) / "SÉ EL PRIMERO" (`components/be-the-first.tsx`) states.
- `data/games.ts` only holds the `Game`/`GameCategory` types and `CATEGORY_FILTERS` — the catalog itself comes from Supabase. `data/home-activity.ts` is still static mock data for the home page.
- Session (`lib/session.ts`, `components/session-provider.tsx`, `useSession()`) is a player name stored in `localStorage` — there is no real Supabase Auth.

### Game engines (`lib/games/`)

- `types.ts` defines the contract: a `GameFactory(canvas, callbacks)` returns a `GameInstance` (`start/pause/resume/restart/end/setInputEnabled/destroy`) and reports through `GameCallbacks` (`onScore/onLives/onLevel/onPauseChange/onGameOver`).
- `registry.ts` maps `gameId → GameEngine` (`{ factory, hasLives? }`). Implemented: `asteroids`, `caida` (Tetris, `hasLives: false`), `bloque-buster` (Arkanoid), `serpentina` (Snake). Games without an engine fall back to a score simulation in `GamePlayer`.
- Each game lives in `lib/games/<id>/` split into `constants.ts`, `entities.ts` (+ `levels.ts` if needed) and `engine.ts` (loop, input, rendering on canvas). Static assets (sprites, sounds) go in `public/games/<id>/`.
- `components/game-canvas.tsx` mounts the engine; `components/game-player.tsx` owns the HUD, pause, "FIN DEL JUEGO" modal and score saving.
- Original JS games used as porting sources are in `references/started-games/`; design mockups (JSX/HTML) in `references/templates/`; raw assets in `references/source-assets/`. These are reference material, not app code.

### Styling & conventions

- Tailwind CSS v4, configured CSS-first: `app/globals.css` uses `@import "tailwindcss"` and defines theme tokens via `@theme inline` (no `tailwind.config.js`). PostCSS is wired through `@tailwindcss/postcss` in `postcss.config.mjs`. Most of the visual system is custom CSS classes in `globals.css` (`.pixel`, `.mono`, `.btn`, `.av-nav`, accent colors cyan/magenta/yellow/green) ported from `references/templates/styles.css`.
- Path alias `@/*` maps to the repo root (`tsconfig.json`).
- Shared components in `components/`, hooks in `hooks/` (e.g. `use-reveal.ts` for scroll reveal), helpers in `lib/format.ts`.
